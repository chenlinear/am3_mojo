# What makes am3_mojo faster

`benchmark.py` and `profile_stages.py` time am3_mojo against the C++ AM³; the main README gives the results under [Performance](../../README.md#performance-am3_mojo-4-threads-vs-the-c-original-serial). On one thread, am3_mojo is already 5.2–6.2x faster, so most of the gain comes from better algorithms. This file names each source of the gain; the docstrings of the code it names explain how.

1. **Inverse-Compton emission from a 2.71 MB table instead of a 236.1 MB kernel** ("photon coeff: pair compton em."). Every step, AM³ streams a dense matrix per emitted photon bin, so memory bandwidth limits it. On AM³'s logarithmic grids the kernel factorises into a table that stays in cache (`ICKernel2D` in `src/am3_mojo/physics/inverse_compton.mojo`). Folding the target photons into the table is a matrix product. It runs in register blocks of 8 × 4 sums, which reuse every value they load from the table 4 times and every photon value 8 times (`ICJob`).
2. **Decay and photo-pion kernels as Toeplitz and Hankel products** ("calc. coeff. neutrino", "calc. coeff. muon", "calc. coeff. proton/neutron"). A decay kernel depends only on an energy ratio, a photo-pion kernel on an energy product. On a logarithmic grid they are thus constant along diagonals or anti-diagonals. A product with them is a SIMD convolution of their diagonal values (`MatD` and `diagonal_gemv` in `src/am3_mojo/utils/linalg.mojo`). The kaon and charm kernels act only on the hadron bins that hold particles. The decays of all pion and muon sets of a step run in one parallel pass. Each kernel serves two vectors per pass over its diagonals (`diagonal_gemv2`).
3. **Bethe–Heitler pair emission and the pair sources** ("calc. coeff. pairs", 20.2–30.8x faster). The kernel is packed into its non-zero rows, and the sums run only over the proton bins that hold particles (`src/am3_mojo/physics/bethe_heitler.mojo`). The muon-decay pair sources are Toeplitz products, as in point 2. With the full $\gamma\gamma$ kernel instead of AM³'s 14-bin approximation, each row of the pair source is a SIMD dot product. Only the part of each row that the sum reads is stored, in the order the sums read it (`Pair` in `src/am3_mojo/physics/pair_production.mojo`).
4. **Cooling rates once per species** ("evolve pion", "evolve muon"). AM³ recomputes the synchrotron and inverse-Compton cooling rates for each component of a species. am3_mojo computes them once per step and species, and updates the species in parallel (`evolve_group` in `src/am3_mojo/simulation/manager.mojo`, `share_cooling` in `src/am3_mojo/solver/solver.mojo`).
5. **SIMD and threads.** The matrix–vector products, the inverse-Compton and photo-pion kernels and the cooling rates use SIMD vectors of 8x float64 (16x float32 for the Bethe–Heitler kernel). The emission, the photo-pion channels, the pair source, the decays, the species updates and the kernel set-up run in parallel (`src/am3_mojo/utils/parallel.mojo`). One thread computes each output element, in a fixed order, so the results are bitwise identical for any thread count. The independent parts of the photon coefficients run as the tasks of one parallel section (`Calc_Coeff_Phot` in `src/am3_mojo/simulation/manager.mojo`). The workers sleep as soon as a section ends: spinning workers would slow down the serial work between the sections. Kernel set-up is 3.6–3.9x faster than in C++ for the hadronic models.
6. **Memory: 0.30 GB instead of 2.92 GB** (blazar model). The inverse-Compton table and the Toeplitz and Hankel forms replace the large dense kernels. AM³ always allocates the full $\gamma\gamma$ pair kernel (1.9 GB, most of its memory); am3_mojo only when that treatment is on, and then only the part of each row it reads (`src/am3_mojo/physics/pair_production.mojo`). The largest part of am3_mojo's peak is the Bethe–Heitler kernel, 120 MB as float32. All arrays are allocated once and updated in place.
7. **Hadron inverse-Compton emission** ("photon coeff: proton/pion/muon compton em.", 5.7–8.4x faster). AM³ loops over every pair of photon and hadron bins; am3_mojo adds the shifted target photons of each non-empty hadron bin only to the photon bins they reach (`HadIC._emit` in `src/am3_mojo/physics/decays.mojo`).
8. **Interpolation between the grids** ("photons -> had. grid", 71.1–87.5x faster). AM³ copies the whole photon spectrum for each hadron bin it fills, every step; am3_mojo reads it in place (`grid_lep2had` in `src/am3_mojo/model/arrays.mojo`).

The grid sizes come from the physics, not from SIMD: 314 hadron, 340 lepton, 464 neutrino and 620 photon bins, at 10 bins per e-fold. The arrays are not padded to the SIMD width.
