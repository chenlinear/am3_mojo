# What makes am3_mojo faster

`benchmark.py` and `profile_stages.py` compare the run times of am3_mojo and the C++ AM³. The main README gives the results under [Performance](../../README.md#performance-am3_mojo-4-threads-vs-the-c-original-serial). On one thread, am3_mojo is already 5.5–7.2x faster, so most of the gain comes from better algorithms. This file names each source of the gain and the code that implements it.

1. Inverse-Compton emission from a 2.71 MB table instead of a 236.1 MB kernel ("photon coeff: pair compton em."): Every step, AM³ streams a dense matrix per emitted photon bin, so memory bandwidth limits its speed. On AM³'s logarithmic grids, the kernel factorizes into a table that stays in cache (`ICKernel2D` in `src/am3_mojo/physics/inverse_compton.mojo`). Folding the target photons into the table is a matrix product. This product runs in register blocks of 8 × 4 sums. These blocks reuse every value that they load from the table 4 times, and every photon value 8 times (`ICJob`).
2. Decay and photo-pion kernels as Toeplitz and Hankel products ("calc. coeff. neutrino", "calc. coeff. muon", "calc. coeff. proton/neutron"): A decay kernel depends only on an energy ratio, and a photo-pion kernel only on an energy product. On a logarithmic grid, they are thus constant along diagonals or anti-diagonals. A product with them is a SIMD convolution of their diagonal values (`MatD` and `diagonal_gemv` in `src/am3_mojo/utils/linalg.mojo`). So is the inverse-Compton photon loss ("photon coeff: pair compton abs."), whose kernel depends only on the product of the photon and electron energies. The pion, muon, kaon and charm decay kernels act only on the hadron bins that hold particles. The decays of all pion and muon sets of a step run in one parallel pass. Each kernel acts on two vectors per pass over its diagonals (`diagonal_gemv2`).
3. Bethe–Heitler pair emission and the pair sources ("calc. coeff. pairs", 26.8–42.1x faster): Four fifths of the pair kernel's non-zero entries have $2\gamma_p\varepsilon \ge 600$. Here $\gamma_p$ is the proton's Lorentz factor, and $\varepsilon$ is the photon's energy in units of $m_e c^2$. For these entries, the integral over the photon energy in the proton's frame stops at 600 $m_e c^2$, the end of AM³'s cross section. Each of these entries is thus a function of the ratio of the $\mathrm{e}^\pm$ and proton energies, divided by $(\gamma_p\varepsilon)^2$. A sum over the photons for each proton bin, then a Toeplitz product over the proton bins, replaces these entries. The rest of the kernel is packed into its non-zero rows, and the sums run only over the proton bins that hold particles (`src/am3_mojo/physics/bethe_heitler.mojo`). The muon-decay pair sources are Toeplitz products, as in point 2. With the full $\gamma\gamma$ kernel instead of AM³'s eight-bin approximation, each row of the pair source is a SIMD dot product. Only the part of each row that the sum reads is stored, in the order that the sum reads it (`Pair` in `src/am3_mojo/physics/pair_production.mojo`).
4. Cooling rates once per species ("evolve pion", "evolve muon"): AM³ recomputes the synchrotron and inverse-Compton cooling rates for each component of a species. Instead, am3_mojo computes them once per step and species, and updates the species in parallel (`evolve_group` in `src/am3_mojo/simulation/manager.mojo`, `share_cooling` in `src/am3_mojo/solver/solver.mojo`).
5. SIMD and threads: The matrix–vector products, the inverse-Compton and photo-pion kernels and the cooling rates use SIMD vectors of 8x float64 (16x float32 for the Bethe–Heitler kernel). The emission, the photo-pion channels, the pair source, the decays, the species updates and the kernel set-up run in parallel (`src/am3_mojo/utils/parallel.mojo`). One thread computes each output element, in a fixed order, so the results are bitwise identical for any thread count. The independent parts of the photon coefficients run as the tasks of one parallel section (`Calc_Coeff_Phot` in `src/am3_mojo/simulation/manager.mojo`). The workers sleep as soon as a section ends, because otherwise they spin and slow down the serial work between the sections. Kernel set-up is 19.9–127.3x faster than in C++ for the hadronic models.
6. Memory: 0.12 GB instead of 2.88 GB (blazar model). The inverse-Compton table and the Toeplitz and Hankel forms replace the large dense kernels. AM³ always allocates the full $\gamma\gamma$ pair kernel (1.9 GB, most of its memory). By contrast, am3_mojo allocates this kernel only when that treatment is on, and only the part of each row that it reads (`src/am3_mojo/physics/pair_production.mojo`). The Bethe–Heitler kernel is packed straight from its diagonals (point 9): 7.6 MB as float32, instead of the 120 MB of the dense kernel. The kernels are allocated by `init_kernels()`, and the synchrotron kernels again in the first step after a change of the field. A step allocates only some vectors of the length of one energy grid.
7. Hadron inverse-Compton emission ("photon coeff: proton/pion/muon compton em.", 5.6–8.5x faster): AM³ loops over every pair of photon and hadron bins. Instead, am3_mojo adds the shifted target photons of each non-empty hadron bin only to the photon bins that they reach (`HadIC._emit` in `src/am3_mojo/physics/decays.mojo`).
8. Interpolation between the grids ("photons -> had. grid", 90.7–90.8x faster): Every step, AM³ copies the whole photon spectrum for each hadron bin that it fills. Instead, am3_mojo reads the spectrum in place (`grid_lep2had` in `src/am3_mojo/model/arrays.mojo`).
9. Bethe–Heitler kernel set-up: The pair kernel depends on the $\mathrm{e}^\pm$ and proton energies only through their ratio. It depends on the photon energy only through $\gamma_p\varepsilon$. On the grids, the kernel is thus a function of two bin differences. So `initialize_kernels` computes 0.13 million values for the kernel's 23 million entries, which AM³ computes one by one (`src/am3_mojo/physics/bethe_heitler.mojo`). This function packs the kernel's non-zero rows straight from these values, so the 23 million entries are never stored (`PackedGemvF.pack` in `src/am3_mojo/utils/linalg.mojo`).

The grid sizes come from the physics, not from SIMD: 314 hadron, 340 lepton, 464 neutrino and 620 photon bins, at 10 bins per e-fold. The arrays are not padded to the SIMD width.
